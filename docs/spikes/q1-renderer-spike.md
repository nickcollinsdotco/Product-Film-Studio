# Q1 renderer spike: how Primitives drive the Renderer

Input for [ADR-0007](../adr/0007-how-primitives-drive-the-renderer.md). Running log with timestamps and evidence paths: `.scratch/q1-renderer-spike/FINDINGS.md`. All paths below are relative to `.scratch/q1-renderer-spike/`, where the spike code and evidence stay. HyperFrames CLI/Studio 0.8.141. Written by the spike agent; saved by the main session, which also spot-checked `out/frames/a-state-0.5-vs-4.5.png` and `evidence/studio-unroll-b3-helpers.diff`.

## Question and criteria

How should Shots built from semantic Primitives (`camera.pushIn()`, `surface.focus()`) drive the CSS 3D Renderer, with Three.js to follow? The user weighted the criteria:

1. **Required:** retiming at the Shot level in HyperFrames Studio, meaning moving and trimming Shot clips (sub-compositions) in the Edit entry file.
2. Required: HyperFrames lint, `check` and `keyframes` diagnostics keep working.
3. **Nice to have:** keyframe-level retiming inside a Shot. Finer changes go through Claude. "Unroll to edit" is undesirable because it rewrites Primitive calls into raw tweens.

The scenario is identical in every variant: 1920×1080, 5 s, 30 fps, two Surfaces in CSS 3D (A near, B 700 px deeper). The Camera pushes in from z 0 to 350 over 0.5–3.5 s (power2.inOut). Focus racks from A to B over 1.5–3.0 s, with blur = k·|depth − focus|.

## Variants

- **`a-state`**: `camera.pushIn(tl, {to, at, duration})` and `surface.focus(tl, "b", {...})` tween a plain `scene` object. One CSS 3D render function in the timeline's `onUpdate` writes the camera transform and per-Surface blur.
- **`b-native`**: the same namespaced Primitive API in an external Library file, `primitives.js`. It emits GSAP tweens on DOM elements and computes blur analytically.
- **`b3-helpers`**: b-native written as top-level helpers with positional arguments, inline in the composition (`cameraPushIn(tl, 350, 0.5, 3)`). This is the only helper shape Studio's parser can inline.
- **`b2-inline`**: literal tweens, no helpers.
- **`c-hybrid`**: the camera is a native element tween through a flat helper; focus distance is scene state, and blur is derived in `onUpdate`.
- **`x-frozen`**: negative control, a-state without `onUpdate`.
- **`edit/`**: an Edit host that mounts each variant as a Shot sub-composition clip (b2-inline twice), plus one Edit-owned Transition tween.

## Key findings

1. **Shot-level retiming doesn't depend on the variant.** In Studio I moved, end-trimmed, start-trimmed and extended a clip for every variant. Studio only ever wrote host attributes in `edit/index.html`: `data-start`, `data-duration`, plus `data-playback-start`. It also grew the root `data-duration` when a clip ran past the end. It never touched the Shot template files (`evidence/edit-index-studio.diff`).

2. **A Shot's internal timeline is never scaled.**
   - Moving a clip shifts it, trimming the end cuts it, trimming the start offsets it via `data-playback-start`, and extending it holds the last frame.
   - Measured against the baseline, every variant matched this shift/cut model at 44–49 dB. A scaled-timeline model fails at about 13 dB (`evidence/retime-compare.txt`).
   - Consequence: Landings inside a Shot can't be moved from Studio. They move with the whole clip, or by changing the Shot's parameters through Claude or code. Studio has no UI for `data-variable-values`.

3. **Shot templates must not put clip timing on inner elements.** In my templates the camera rig and Surfaces carried `class="clip" data-duration="5"`. Extending a Shot to 7 s therefore showed an empty background after 5 s. With those attributes removed, the Shot holds its last frame (`edit-hold/`; frames at 3.9 s and 6.5 s are identical).

4. **Edit-owned Transitions follow the clip.** A literal host tween on `#shot-2` was rewritten when I moved and trimmed that clip: position 5 → 6 and duration 0.5 → 0.4, scaled by the trim. Transitions written as literal host tweens stay in sync with Shot retimes.

5. **Studio's keyframe editor only reads source; it doesn't look at the running timeline.**
   - It parses only the first inline script containing `gsap.timeline`, so external Library files are invisible.
   - Helper calls are inlined only for top-level functions with positional arguments, and they show as "Generated by f()". The only way to edit them is Unroll, which deleted the helper and replaced the call with a raw `tl.fromTo` (`evidence/studio-unroll-b3-helpers.diff`).
   - Namespaced calls like `camera.pushIn()` are never inlined.
   - Only literal tweens edit directly. Retiming the Camera's "Starts at" in b2 changed exactly one source line (`evidence/studio-keyframe-retime-b2-inline.diff`).
   - `filter` tweens are editable in the Motion panel but get no timeline lane.

6. **Diagnostics.** lint, `check` and its motion audit work by actually playing the composition, so they work for every variant. The motion audit caught the missing renderer in `x-frozen` (`motion_frozen`). `keyframes`, including `--shot`, only sees tweens it can read from source, so it covers nothing in a-state or b-native.

7. **Shared inner ids cost an optimisation.** Reusing `#camera` across Shot templates rendered correctly. But the compiler marks every Shot with `data-hf-scene-no-swap="a script outside the scene selects #camera"`, which turns a HyperFrames optimisation off. Inner ids should be prefixed per template.

## Recommendation for ADR-0007

**Scene state (a-state): Primitives tween renderer-neutral scene state, and one render function per Renderer draws the frame.**

- The required criterion is met equally by every option, so it doesn't decide anything.
- What does decide: a-state is the only shape where Shots stay purely semantic and the Renderer is a swappable function. That is what ADR 0002 needs for Three.js.
- It also handles derived values like depth of field in general. b's analytic blur is only exact when no Surface lies between the two focus depths.
- The cost is the nice-to-have (keyframe editing in Studio) and `keyframes` CLI coverage inside Shots. Native helpers don't usefully recover either: Studio shows them read-only with Unroll. Only literal inline tweens are editable, and those aren't Primitives.
- Adopt these alongside it:
  - every Shot template ships a `*.motion.json` sidecar so `check` verifies its motion;
  - no clip timing on inner elements;
  - template-prefixed ids;
  - Edit-level Transitions written as literal host tweens.

**Library helpers don't need to stay statically visible.** Keep the Library as an external file, copied into each Project per ADR 0004. Inlining it into every synced composition only buys read-only display plus Unroll. It costs a positional-argument API and duplicated code. If keyframe editing in Studio ever becomes important, the only shape that works is literal tweens, which means a code generator, and ADR 0003 rejected that.

## Caveats and what I could not verify

- **Synthetic drags.** Studio drags were real clicks plus synthetic pointer events in the page, because the browser tool has no native drag. Studio's own handlers processed them and wrote the files. The keyframe retime used real keystrokes.
- **Stale UI.** Clip labels in the Studio UI were sometimes stale until a reload. Once, editing twice without reloading showed "Unable to patch timeline element shot-1". The files on disk were correct every time.
- **Not tested:**
  - a Studio extend on the template version that holds its last frame (I edited the host by hand for that test);
  - the b3 Surface panels (inferred to show the same "Generated by surfaceFocus()" notice);
  - a real Three.js Renderer;
  - Studio's "+ Add effect" on a-state/b-native elements, which would likely add a competing tween.
- **Audit policy.** Contrast and layout audits flag the deliberately blurred, overlapping Surfaces. This needs a policy, for example `data-layout-allow-overlap` plus a contrast exemption for out-of-focus Surfaces.
- **Fake content.** The scene uses fake div dashboards, not real Screens.
